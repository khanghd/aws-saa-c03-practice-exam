Debug permission denial

  • Inspect active rules across all scopes trước, xác định rule nào đang chặn
  • Không disable toàn bộ permission system, không lặp lại thao tác bị chặn, không cấp Bash không giới hạn để né lỗi

CLAUDE.md & subagent

  • CLAUDE.md (project-scoped, commit) = persistent context, tự load mỗi session → khỏi giải thích lại convention mỗi lần
  • Subagent riêng chỉ hợp lý khi có recurring specialized task cần system prompt/tool permission/model riêng — không tạo cho việc ad-hoc một lần
Credential hygiene: không bao giờ đặt API key/credential trong .claude/settings.json hay prompt context (leak qua log/trace) → resolve runtime từ secret store / per-user OAuth scoped token.

2. Least privilege & tool / agent design

Per-role allow-list

  • Scoped đúng nhu cầu, enforced ở orchestration layer
  • Sai khi: "allow all + để model tự decline", "allow every tool", hoặc "disable hết" (quá tay)

Production database guardrail chuẩn

  • Read-only credential mặc định
  • Subagent chỉ được gán tool read-only
  • Yêu cầu human confirmation trước mọi thao tác ghi/sửa dữ liệu

Context budget / tool sprawl

  • Nhiều MCP server → tool definitions load hết upfront → nuốt context trước khi user gõ gì
  • Fix: Tool Search / progressive tool discovery (nạp theo nhu cầu) — không phải disable hết MCP hay thêm server mới
  • Tool catalog phình to theo thời gian (6 → 34 tools) → description overlap, accuracy giảm
  • Dấu hiệu cần curate lại theo domain, không phải thêm guardrail chung chung

5. Token / cost / latency optimization

Nên làm

  • Prompt caching cho static/repeated prefix (system prompt, policy preamble) → giảm cost mà không đổi accuracy
  • Model routing: query đơn giản → Haiku, case phức tạp → Opus → giảm đồng thời cost & p95 latency
  • Giảm retrieval depth (top-k) khi latency là constraint chính

Không bao giờ đúng

  • Tăng max_tokens để giảm latency
  • Thêm few-shot examples tùy tiện vào mọi request
  • Chuyển toàn bộ traffic sang heaviest/flagship model "cho chắc"
  • Nạp full corpus vào context; tắt hẳn prompt caching

Token-management theo lifecycle request (hay ra dạng match)

Giai đoạnTactic
Input PreparationTrim retrieved passages còn span liên quan; summarize lịch sử hội thoại cũ
Prompt ConstructionSắp cacheable content lên trước per-request content; đưa nội dung tĩnh vào cacheable prefix
Output HandlingValidate structured output theo schema; persist output đã validate để audit

6. Security & guardrails

  • Indirect prompt injection = data exfiltration điển hình: adversarial content trong retrieved document chỉ đạo model gọi outbound tool gửi dữ liệu ra URL kẻ tấn công kiểm soát. Mitigation chuẩn: treat mọi nội dung retrieved/external là untrusted input + input classifier + output validation.
  • Combo chặn admin-bypass/jailbreak: prompt-level "untrusted data" + runtime classifier phát hiện override + scoped permission không thể bị user content nâng quyền + audit logging — thiếu 1 trong 4 lớp là chưa đủ.
  • Credential hygiene: không đặt trong prompt context; resolve từ secret store; per-user OAuth token scoped thay vì 1 API key dùng chung; tool-call log phải có actor attribution.

Guardrail layering chuẩn (vd chặn tư vấn đầu tư)

  • Input guardrail: out-of-scope category + fixed refusal trong system prompt
  • Output guardrail: output classifier chặn response vi phạm
  • Sai: tăng temperature, giới hạn session length, chỉ log để review sau

Risk ↔ control matching

  • Outbound tool allowlist + per-call review → chặn data exfiltration
  • Adversarial eval set chạy lại mỗi lần đổi model version → bắt silent quality drift
Observability gap thật sự: model identity/version không ghi theo turn; correlation ID không propagate xuyên agent & tool calls. Trace span, latency/token metrics, redacted tool-call log là best practice — không phải gap.

Skill đã có đủ disclaimer/prohibited-language → vẫn còn 2 trách nhiệm PHẢI giữ ở application layer: (1) xác thực user được phép dùng (authN/authZ), (2) audit logging — LLM/Skill không tự đảm bảo 2 việc này tin cậy 100%.

7. Compliance (HIPAA / GDPR)

HIPAA

  • Claude Enterprise + ký BAA + Zero Data Retention + audit logging
  • Free/cá nhân không đủ điều kiện dù có log hay không
  • Tắt hết logging không đồng nghĩa compliant (vẫn thiếu BAA)

GDPR (EU deployment)

  • Cần Enterprise-tier + ký DPA
  • Xác định rõ data-residency/retention theo yêu cầu

Trình tự đánh giá tuân thủ một regulation cụ thể

Xác định regulation applicable (data type, jurisdiction, audience)→ Inventory compliance tooling sẵn có→ Map data flow → clause→ Gap-analysis & remediation→ Document & signoff

8. Evaluation, testing & monitoring

Trình tự xây evaluation pipeline

Define metrics & slices (representative/edge/adversarial)→ Curate & label dataset theo slices→ Chạy chấm điểm/score→ Review failure case với SME→ Publish dashboard & gate release
Test typePhát hiện gì
RegressionThay đổi prompt/code làm hỏng case đã pass trước đó (so với stable reference set)
AdversarialLỗ hổng an toàn / prompt-injection
IntegrationHành vi end-to-end giữa các component
SmokeHệ thống chạy được sau deploy, không đánh giá chất lượng chi tiết

Evaluation set bias

  • Set hẹp ở 1 region/tenure band → expand coverage rồi re-score trước khi release rộng — không giữ nguyên dù score cao

Metric phải match đúng requirement

  • An toàn dữ liệu + cost ceiling → dùng RBAC enforcement rate + per-query token cost, không dùng BLEU/throughput khi câu hỏi không hỏi performance

Trình tự khác hay gặp

A/B test: define hypothesis & metric→ xác định sample size cho power→ chạy random-assignment experiment
Model selection: define quality bar/latency/volume→ chọn candidate theo requirement→ test trên representative sample
Bias/fairness traps: approval-rate parity ≠ error-rate parity giữa protected group · match-rate cao với human không chứng minh hết bias (có thể kế thừa bias con người) · acceptance rate cao (89–94%) không đủ nếu user đang override vì model bỏ sót tiêu chí → đó là scope gap, không phải bằng chứng "đủ tốt".

Phát hiện 1 lần fabricated citation: sample output gần đây đo fabrication frequency + review citation-grounding control trong pipeline — không tắt hệ thống ngay, không phủ nhận, không coi là ca đơn lẻ rồi bỏ qua.

9. Human-in-the-loop (HITL) & risk governance

Risk-stratified sampling

  • Review 100% output low-confidence + high-impact
  • Cộng random sample nhỏ cho output routine/high-confidence
  • Không review 100%, không chỉ dựa vào complaint (passive/reactive)

Escalation criteria chuẩn

  • Confidence score dưới ngưỡng + high-impact category + ambiguity flag từ classifier + user's explicit request
  • Không escalate tùy hứng hay chỉ sau khi khách complain
Identify assets & sensitivity→ enumerate threat actors/vectors→ assess likelihood/impact→ recommend mitigation→ document & residual-risk signoff

Delegation scope dựa theo loại rủi ro, không dựa theo transaction size (vd không tự miễn human review cho refund nhỏ chỉ vì số tiền thấp, nếu loại quyết định vẫn nhạy cảm).

10. Documentation & communication theo audience

Handoff package đầy đủ: Architecture overview + ADRs + component-level diagrams + evaluation framework (kèm reference set) + runbooks + on-call playbook + known-limitations register.

ADR phải có đủ: context, decision, alternatives considered, trade-offs/consequences, date & authors. Thiếu alternatives → yêu cầu author bổ sung trước khi publish — không approve nguyên trạng, không xoá ADR.
AudienceNội dung cần dẫn đầu
Executive sponsorBusiness outcomes đạt được, trade-offs đã chấp nhận, risk tổng quan
Security & compliance reviewerThreat model, control mappings, residual-risk acceptance criteria, audit traceability
Product managerCapabilities delivered, roadmap dependencies
Engineering / delivery teamComponent responsibilities, interface contracts, sequence diagram, config defaults, runbooks
Mixed audience (exec + engineering)Lead với decision & business outcome trước, rồi mới kỹ thuật

Strong decision-communication có: ownership + review cadence khi assumption thay đổi, VÀ alternatives considered kèm tiêu chí đánh giá — không lược bỏ alternatives để "gọn".

11. Discovery & requirements

  • Request mơ hồ ("AI để sửa customer escalation") → decompose bằng targeted question: ai escalate, trigger nào, resolution tốt là gì, constraint nào (latency/cost/audit/data sensitivity) — không thiết kế ngay, không hoãn vô thời hạn, không áp kinh nghiệm cũ chưa validate
  • Functional = hành vi cụ thể (extract field, classify, draft); non-functional = ràng buộc đo lường được (vd p95 latency < 800ms)
Xác định audience & câu hỏi guide cần trả lời→ outline sections

12. Lifecycle & stakeholder management

  • Continuity: mang evaluation framework + reference set qua các phase + ghi lại lessons learned cuối mỗi phase
  • Feedback session hiệu quả: agenda rõ ràng + share artifact trước + ghi lại decision & follow-up
  • Scope creep giữa chừng: acknowledge request, nêu rõ ảnh hưởng scope/timeline minh bạch — không âm thầm nhận thêm, không từ chối cứng nhắc
  • Quay lại design (không chỉ iterate) khi kiến trúc hiện tại không đáp ứng được requirement mới nếu không đổi nền tảng

Trình tự ("step BEFORE/AFTER")

  • Bước đầu hầu như luôn là: define/identify/enumerate/inventory
  • Bước cuối hầu như luôn là: document & sign-off, hoặc roll out/publish dashboard
  • "Assess threats/impact" luôn SAU "identify assets + enumerate threat actors"
  • "Map data flow → clause" luôn SAU "xác định applicability + inventory tooling"
  • "Test model trên sample" luôn SAU "define quality bar + chọn candidate"

"Select TWO" — mẹo

  • Mỗi lựa chọn được chấm độc lập như true/false — không phải chọn cặp "nghe hợp nhau"
  • "...part of the solution" → 2 đáp án bổ sung nhau, không cái nào tự đủ
  • "...complete solution" → 2 đáp án độc lập, mỗi cái tự đúng riêng

Dạng Yes/No & Match

Yes/No

  • Chấm từng dòng độc lập — statement dùng từ tuyệt đối (always/identical/regardless) → No
  • Mô tả đúng đặc tính có điều kiện/ngữ cảnh → Yes; khái quát hoá/đánh đồng khái niệm → No

Match/ghép nhóm

  • Đọc hết option-group trước khi ghép dòng đầu tiên
  • Group thường chia theo layer/giai đoạn: Pre/Model/Post-Processing; Input Prep/Prompt Construction/Output Handling

Ba câu hỏi tự kiểm trước khi chốt đáp án

  • Control này được enforce tại layer nào — có thể bị user/content vượt qua không?
  • Đáp án có đúng đủ (not too broad, not too narrow) với đúng giai đoạn lifecycle đang hỏi không?
  • Tài liệu/communication này có đúng đối tượng đang cần đọc nó không?
