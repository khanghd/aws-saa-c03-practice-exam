Lưu trữ Performing

S3 là dịch vụ ra nhiều nhất trong đề. Phải thuộc storage class, và biết khi nào EBS/EFS/FSx thắng S3.

Mã hóa S3

  • SSE-S3 — AWS tự quản lý key, AES-256
  • SSE-KMS — key do khách hàng quản lý, có audit trail qua CloudTrail, có quota request (dùng S3 Bucket Keys để giảm số lần gọi KMS)
  • SSE-C — khách hàng tự cung cấp key, AWS không lưu key
  • Client-side — mã hóa trước khi upload

Transfer / access S3

  • Transfer Acceleration → upload nhanh qua edge location cho khoảng cách xa
  • Multipart upload cho file >100MB (bắt buộc khi >5GB)
  • Pre-signed URL → cấp quyền truy cập tạm thời mà không đổi bucket policy
  • S3 Object Lambda → biến đổi dữ liệu ngay khi GET, không cần tạo bản sao

DynamoDB — cần nhớ

  • On-Demand → tải khó đoán, trả theo request
  • Provisioned + Auto Scaling → tải ổn định dự đoán được, rẻ hơn khi scale lớn
  • GSI → partition/sort key khác, chỉ eventually consistent
  • LSI → cùng partition key, sort key khác, phải tạo ngay lúc tạo bảng
  • DAX → cache in-memory, đọc ở mức microsecond, tương thích API
  • Global Tables → replicate multi-region active-active
  • TTL → tự xóa item hết hạn, miễn phí
  • Streams → bắt thay đổi dữ liệu → trigger Lambda

Load balancer

ALB

  • Layer 7, HTTP/HTTPS, routing theo path/host
  • WebSocket, target là container/Lambda

NLB

  • Layer 4, độ trễ cực thấp, hỗ trợ static IP/EIP
  • Hàng triệu request/giây, TCP/UDP

Route 53 — routing policy

Simple · Weighted (A/B, chia % traffic) · Latency-based (region độ trễ thấp nhất) · Failover (active-passive + health check) · Geolocation (theo vị trí user, compliance) · Geoproximity (thiên lệch theo khoảng cách, cần Traffic Flow) · Multivalue (LB đơn giản phía client + health check)

CloudFront

Dùng Origin Access Control (OAC) để chỉ cho CloudFront truy cập origin S3. Signed URL/Cookie cho nội dung private theo user/path. Field-level encryption cho field nhạy cảm trong form. Lambda@Edge / CloudFront Functions để xử lý request/response ngay tại edge.

Identity

IAM Role vs User

  • Role → credential tạm thời (STS), được assume bởi service/app/federated user — không hardcode key trên EC2
  • Truy cập cross-account → dùng role + trust policy, không dùng chung IAM user

Cognito

  • User Pools → đăng ký/đăng nhập, directory người dùng
  • Identity Pools → cấp credential AWS tạm thời cho user của app (kể cả guest)

Guardrail toàn tổ chức

SCP (Organizations) giới hạn mức permission tối đa — SCP không bao giờ cấp quyền, chỉ hạn chế. Permission boundary giới hạn mức permission tối đa của 1 entity IAM. WAF = lọc Layer 7 (SQLi/XSS, rate-based rule) gắn vào ALB/CloudFront/API GW. Shield Standard = miễn phí, tự động chống DDoS; Shield Advanced = trả phí, chống DDoS L3/4 + bảo vệ chi phí + DRT 24/7.

Bẫy: "Policy khắt khe nhất thắng" — explicit Deny luôn override Allow, áp dụng cho mọi loại policy (IAM, SCP, resource policy, permission boundary).

Tối ưu chi phí Cost

Công cụ

  • Cost Explorer → trực quan hóa/dự báo chi phí
  • Trusted Advisor → tài nguyên idle, EBS dùng ít, kiểm tra bảo mật
  • Compute Optimizer → gợi ý rightsizing
  • AWS Budgets → cảnh báo theo ngưỡng

Quy tắc cần nhớ

  • Tải ổn định 24/7 → Reserved/Savings Plan
  • Có thể gián đoạn/batch → Spot
  • Lifecycle rule S3 để tự transition/expire
  • NAT Gateway tính phí theo giờ + GB — gộp bớt nếu cần tiết kiệm (nhưng mất tính cách ly theo AZ)

Giám sát & vận hành Resilient

CloudWatch = metric, alarm, log, dashboard (hiệu năng/vận hành, "đang xảy ra gì"). CloudTrail = lịch sử gọi API/audit ("ai đã làm gì" — governance/compliance). Config = lịch sử cấu hình resource & rule compliance theo thời gian ("cái gì đã thay đổi, có compliant không"). X-Ray = distributed tracing giữa các microservice.

Bẫy thường gặp trong đề thi

"Tiết kiệm chi phí nhất" + tải ổn định → Reserved/Savings Plan, không phải Spot (Spot dành cho fault-tolerant/linh hoạt, không phải cứ rẻ là chọn).
"Ít operational overhead nhất" → luôn trỏ tới dịch vụ managed (Aurora Serverless, Fargate, DynamoDB) thay vì dịch vụ tự quản lý.
Static website + HTTPS + custom domain → S3 static hosting + CloudFront + ACM, không dùng S3 website endpoint đơn thuần cho HTTPS.
"Cross-account" hoặc "cross-region" access → nghĩ tới IAM role + STS AssumeRole hoặc Resource Policy, không phải chia sẻ credential.
"Mã hóa volume EBS chưa mã hóa" → không mã hóa in-place được: tạo snapshot → copy snapshot kèm mã hóa → tạo volume mới.
Lambda trong VPC cần internet → vẫn cần NAT Gateway ở private subnet; nằm trong VPC không tự nhiên có internet.
Failover DB dưới 1 giây → Aurora Global Database / Multi-AZ, không phải read replica (replica async + phải promote thủ công).
"Session phải sống sót khi instance chết" / tầng ASG stateless → đẩy session ra ElastiCache/DynamoDB, không chỉ dựa vào sticky session.
